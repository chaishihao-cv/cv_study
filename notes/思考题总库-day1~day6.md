# day1 · 梯度下降（5 道练习）

## 练习 1（推导）`∂L/∂w` 怎么来的，为什么多乘一个 x

**答案**

```text
L = (1/n) Σ (w*x_i + b - y_i)^2
令 e_i = w*x_i + b - y_i
∂L/∂w = (2/n) Σ e_i * x_i
∂L/∂b = (2/n) Σ e_i
```

**为什么多乘 x**：链式法则两层——外层对 `(wx+b-y)` 求导得 `2e`，内层 `(wx+b-y)` 对 `w` 求导得 **`x`**。

**直觉**：`x` 大的样本，`w` 稍微一动，预测就偏很多 → **`w` 对它的误差"责任更大"，所以梯度里带着它的权重。**

**反过来也成立**：`x=0` 的样本对 `∂L/∂w` 贡献 0（`w` 怎么变都不影响它），但它对 `∂L/∂b` 有贡献。

## 练习 2（预测）`lr=0.05` 跑 200 轮会怎样

**答案（推理，不是背数字）**

```text
lr 从 0.1 减半 → 每步只走一半 → 到达同样精度约需 2 倍轮次
曲线形状相同（前快后慢的指数衰减），但整体更缓
200 轮能收敛到很低，但比 lr=0.1 的 200 轮略高一点点
```

**关键不是这个数，是这条规律**：**lr 与收敛轮次近似成反比**（`lr 减半 → 轮次翻倍`），但**不是精确反比**，因为越接近谷底梯度越小，小 lr 在尾部会"走不动"，可能停在略高的 loss。

**反过来**：`lr` 放大 10 倍不会快 10 倍，**会震荡甚至发散**（越过谷底来回跳）。

## 练习 3（迁移）把损失换成 `mean(|pred-y|)`

**答案**

```text
∂L/∂w = (1/n) Σ sign(e_i) * x_i      （sign 就是 ±1）
```

**三个对比**：

| 问题 | L1（绝对值） | MSE（平方） |
|---|---|---|
| 梯度大小 | 恒为 ±1×x，**与误差大小无关** | 与误差**成正比**，误差大时梯度大 |
| 收敛 | 误差大时反而"敢走"；**最优附近恒速横跳，不收敛到精确点** | 近处梯度自然变小，**收敛平稳精确** |
| 离群点 | **影响小**（+50 的点只贡献 1 份梯度） | **影响极大**（50² = 2500 份） |

**一句话**：**L1 抗离群点但尾部震荡，MSE 尾部精确但怕离群点。** 折中方案是 Huber loss（小误差用平方、大误差用线性）。

## 练习 4（判读）三条 loss 曲线分别是什么病

**答案**

| 曲线 | 诊断 | 原因 |
|---|---|---|
| 贴地不动，几乎一条直线 | **lr 太小**（或梯度消失 / 学习率被清零） | 每步更新量小于浮点噪声，看起来没动 |
| 先降后爆，越跑越大 | **lr 太大** | 一步跨过谷底，越跳越远，最终 NaN |
| 50 轮后变平且不再下降 | **lr 合适**（也可能只是收敛了） | 梯度自然变小，正常收敛 |

**判读口诀**：**不动看步长，爆炸看步长，变平正常。** 前两个都调 lr，只是方向相反。

## 练习 5（口述）200 字讲"梯度下降"，禁用"梯度""损失""参数""收敛"

**参考答案**

> 想象你蒙着眼站在一片起伏的山坡上，目标是走到最低的洼地。你看不见路，只能把脚贴在地上，感受哪边比脚下更低、低多少。然后朝那个方向迈一小步，步子大小由你决定：迈太大容易一脚跨过洼底冲到对面山坡，迈太小一天也走不到。走完一步，再重新感受地面，再迈一步，如此反复。每一次只依赖"脚下这一点点的倾斜"，不看全局地图，所以你可能会走进一个小坑误以为到终点。这个笨办法之所以管用，是因为"哪边更低"这个局部信息里已经包含了通向洼地的方向。

**这段里对应了五个东西**：山坡=目标函数；脚贴地感受倾斜=求导；朝低处迈步=更新；步子大小=学习率；小坑=局部极小。

# day2 · 激活函数与梯度消失（10 道自测题）

## 1. sigmoid 的导数公式、最大值、在哪取到

```text
σ'(x) = σ(x) * (1 - σ(x))
最大值 = 0.25，在 x = 0 处（此时 σ(0) = 0.5）
```

**记住"最大值 0.25"这一个数**：它就是"一层最多只能把信号打 4 折"的来源。

## 2. tanh 的导数最大值、为什么比 sigmoid 好

```text
tanh'(x) = 1 - tanh(x)^2
最大值 = 1.0，在 x = 0 处
```

**两个优势**：

1. **导数峰值 1.0 vs 0.25**：同样 10 层，`1^10 = 1` 不衰减，而 sigmoid 是 `0.25^10 ≈ 1e-6`。**同等深度衰减慢 4 倍/层**
2. **零中心**：输出 `-1 ~ 1`，均值接近 0。sigmoid 输出恒正，导致同一层所有梯度同号，更新只能"一起往一个方向走"，**收敛慢、zigzag**

## 3. 10 层、每层导数 0.25，第 1 层收到多少？为什么不是"稍微小一点"

```text
0.25^10 = 9.537e-07      约百万分之一
```

**为什么是指数级**：反向传播每过一层**乘一次**（链式法则），**连乘 10 次 → 指数**。不是"每层减一点"（那是线性的，10 层还剩 0.25×10 的量级）。

**这就是我上次答错那题的核心**：要点在"**连乘**"两个字。

## 4. 梯度消失时 loss 什么样？和"梯度为 0"的区别

| 情况 | loss 表现 | 本质 |
|---|---|---|
| 梯度消失 | **能降，但降得极慢，停在次优** | 有信号，只是弱 |
| 梯度为 0（死区） | **完全不降，一条平线** | 没有任何信号 |

**"loss 不降" ≠ 梯度消失**，那是死区。梯度消失是"学，但学得比蜗牛还慢"。

## 5. 为什么把学习率调大救不回梯度消失

```text
更新量 = lr × 梯度
梯度已经是 1e-7 量级，lr 放大 10 倍 → 更新量 1e-6，仍几乎为 0
lr 放大 1e7 倍 → 前面的层刚能动，后面的层直接爆炸（梯度在 1e-1 量级）
```

**一个 lr 无法同时满足差 6 个数量级的两层。** 病根在**结构**（连乘衰减），不在步长。

## 6. `0.25^20` 和 `0.25^10` 差多少倍

```text
0.25^10 ≈ 9.54e-07
0.25^20 ≈ 9.09e-13
差约 1,000,000 倍
```

**规律**：**层数翻倍 → 衰减平方 → 差一个百万级。** 所以深度一上去就"突然完全不学"，不是线性退化。

## 7. ReLU 为什么缓解梯度消失？它自己的缺陷是什么

**缓解**：正区间**导数恒为 1**，连乘 `1×1×...×1 = 1`，不再衰减。**它把"乘法"变成了"乘法 by 1"。**

**缺陷**：负区间导数**恒为 0**。一旦某神经元的输入长期为负，梯度永远是 0，**权重再也不更新 → 这个神经元"死了"（Dying ReLU / ReLU 死区）**。

**实测证据（`day2_buchong.py`）**：

```text
x = [-2, -1, -0.5]，requires_grad=True
y = relu(x).sum() → backward
x.grad = tensor([0., 0., 0.])      ← 三个全 0，一点梯度都没有
```

## 8. Leaky ReLU 的 `alpha=0.01` 干什么用

**给负区间留一个很小的斜率 0.01**：负区间导数变成 0.01 而不是 0 → **梯度不为 0，神经元不会彻底死掉**。

**代价**：负半轴仍有轻微衰减（0.01 连乘也会衰减，只是慢得多）。

## 9. ResNet 的 `y = F(x) + x` 为什么解决梯度问题

```text
∂y/∂x = ∂F/∂x + 1
```

**那个 `+1` 是一条"恒等捷径"**：不管 `F` 多深、梯度多小，**总有一条路径把梯度原样（乘 1）传回去**。所以 100 层网络也不会衰减到 0。

**它解决的不是"每层衰减变小"，而是"给梯度修了一条不衰减的路"。**

## 10. 怎么用代码诊断"梯度是不是消失了"

```python
for name, p in model.named_parameters():
    if p.grad is not None:
        print(name, p.grad.norm().item())
```

**看什么**：从后往前逐层打印梯度范数。

| 现象 | 结论 |
|---|---|
| 各层量级相近（都在 1e-2 ~ 1e-3） | 健康 |
| 越靠前越小，**每层掉一个数量级** | 梯度消失 |
| 某层恒为 0 | 死区 |
| 越靠前越大 | 梯度爆炸 |

# day3 · Tensor 与 autograd（4 道思考题）

## 1. `no_grad()` 用在训练的哪一步？为什么

**答案**：用在**不需要更新参数的所有前向计算**上——评估/验证、推理、生成数据、可视化。

**为什么**：

```text
它不建计算图 → 不保存中间激活 → 省显存（推理时显存常能省一半以上）+ 更快
```

**注意边界**：**训练循环里的前向（要 backward）不能用它**；推理要 `model.eval()` + `torch.no_grad()` 两个一起。

## 2. 记录 loss 为什么必须 `.item()`，不写会怎样

**答案**：

```text
loss 是带 grad_fn 的张量 → 保留它 = 保留整条计算图
累积到列表里 → 每一轮的图都不释放 → 显存随轮数线性上涨，最终 OOM
```

**还有两个副作用**：张量累加比 float 慢；`.item()` 取的是纯 Python 数，日志/画图才干净。

**一句话**：**`.item()` 不是"取值"，是"断图"。**

## 3. `detach()` 和 `no_grad()` 有什么区别

| | `detach()` | `no_grad()` |
|---|---|---|
| 作用粒度 | **单个张量** | **一段代码块** |
| 做什么 | 返回一个和计算图断开的**新张量**（共享内存） | 块内**新建的所有操作**都不建图 |
| 原张量 | **仍然在图里，仍可 backward** | — |
| 典型用法 | 目标网络、截断 BPTT、冻结某分支 | 推理、评估 |

**关键区别一句**：**`detach()` 剪断一根线，`no_grad()` 关掉整台录像机。**

## 4. 模型在 GPU、数据在 CPU，报什么错，怎么修

**报错原文**：

```text
RuntimeError: Expected all tensors to be on the same device,
but found at least two devices, cuda:0 and cpu!
```

**修法（三处都要搬）**：

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model = model.to(device)
x = x.to(device)          # 每个 batch 都要搬
y = y.to(device)          # 标签也要搬（算 loss 时）
```

**常被漏的两处**：① 新建的辅助张量（如 `torch.zeros(...)`）默认在 CPU；② 从 DataLoader 里取出的 batch 不会自动上 GPU。

# day4 · MLP 训练 MNIST（4 道思考题）

## 1. 反向传播更新的是什么？loss？输入？参数？

**答案**：**更新的是参数（weight 和 bias）**。

```text
loss：只是一个标量，是"评分"，自己不更新（它没有"值"可改）
输入：是数据，是常量，不参与更新（除非做对抗样本/可视化，那时才求 ∂loss/∂x）
参数：optimizer.step() 唯一动的东西
```

**对应代码**：`loss.backward()` 算的是 `∂loss/∂参数`，`optimizer.step()` 拿这个去改参数。

## 2. 为什么推理不需要算梯度？硬要算会多花什么

**答案**：推理只要**前向数值**，不更新任何东西，**梯度和结果毫无关系**。

**硬算的三项成本**：

```text
① 建计算图：每个算子存反向所需的中间激活 → 显存显著增加（约 1.5~2 倍）
② 时间：记录图 + 可能的额外开销 → 变慢
③ 风险：忘了 zero_grad 会累积一堆用不上的梯度
```

**这就是"训练慢、推理快"的一个隐藏原因。**

## 3. `optimizer.zero_grad()` 忘写，loss 曲线什么样？为什么

**答案**：**梯度累加** → 等效学习率随轮数线性放大 → 曲线**越来越抖，最终爆炸或 NaN**。

```text
第 1 批：更新用 g1        → 正常
第 2 批：更新用 g1+g2      → 步长约 2 倍
第 10 批：用 Σg           → 步长约 10 倍
```

**症状辨识**：loss 前几轮还降，**之后开始剧烈震荡，振幅一轮比一轮大**——这几乎一定是忘 zero_grad 或 lr 过大，两者可从"振幅是否单调增长"区分。

**注意**：`loss.backward()` 是**累加**梯度（不是覆盖），这是设计如此（为了支持梯度累积训练大 batch）。

## 4. 为什么最后**不要**加 softmax 再传给 `CrossEntropyLoss`

**答案**：**`CrossEntropyLoss` 内部已经做了 `log_softmax` + `NLL`**，你再加一次 softmax 等于**做了两遍归一化**。

**后果**：

```text
两次 softmax → 概率分布被"压平"（更接近均匀）
→ 正确类的概率被压小 → 梯度变小 → 学得慢，甚至学不动
```

**正确做法**：模型输出层**直接给 logits**（原始分数，可为任意实数）。

**反过来**：推理时想看概率，才需要自己 `softmax`；或者用 `nn.NLLLoss` 配 `log_softmax`——**组合只有两种**：

```text
logits + CrossEntropyLoss          ✓
log_softmax + NLLLoss              ✓
softmax + CrossEntropyLoss         ✗ 做两遍
```

# day5 · 卷积尺寸/参数量/FLOPs（4 道思考题）

> 这四题的详细版答案在 `day5.md` 第十一章，下面是浓缩版。

## 1. MLP 与 Conv 第一层参数量差多少倍？放大到 1080p 呢

```text
MLP  224×224×3 → Linear(150528, 128): 150,528*128 + 128 = 19,267,712   （约 1927 万）
Conv Conv2d(3, 64, 3):                  3*3*3*64 + 64     =      1,792
差 10,752 倍

1080p（1920×1080×3 = 6,220,800）→ Linear(6220800, 128): 796,262,528   （约 7.96 亿）
差约 44.4 万倍；光这一层的权重就要 3 GB 显存，4GB 的 3050 直接放不下
```

**结论**：**MLP 参数量随图像面积线性爆炸，卷积完全不随。**

## 2. "局部连接"和"权重共享"各解决什么死穴？为什么"7 挪一格还是 7"

| 机制 | 解决的死穴 |
|---|---|
| **局部连接** | **参数量爆炸**：每个输出只连 3×3×3 = 27 个输入，不是 15 万个 |
| **权重共享** | **平移等变** + **参数与图像尺寸无关** |

**"7 挪一格还是 7"**：核里那组权重（检测竖边的那 9 个数）在位置 A 用一次、在 A+1 再**用同一组**再算一次。图案整体右移一像素 → 响应值**完全一样**，只是出现在右一格。

**换成 MLP**：每个像素位置配一套独立权重，图案挪一像素后**对应关系全乱**，同一图案得到完全不同的输出 → 学不会"位置无关的特征"。

## 3. 640 个参数却 173M FLOPs，划算吗

**答案**：**划算。**

```text
86,704,128 MACs ÷ 1,728 个乘法权重 = 50,176 = 224×224
即每个权重被复用 50,176 次
```

**三个理由**：

```text
① 算力便宜：173M FLOPs 在 3050 上约 0.02 毫秒（理论）
② 存储与泛化贵：参数少 → 权重 82 KB（CNN）vs 409 KB（MLP）→ 好部署、不易过拟合
③ 边缘设备上"省权重"比"省算力"值钱得多
```

**什么时候不划算**：极小图（如 8×8，复用只有 64 次）、极低端 MCU（连 173M 都跑不动）。

## 4. 参数少 5 倍、精度只高 1 个点、还更慢——CNN 到底强在哪

**答案**：**强在"归纳偏置"，不在 MNIST 的准确率。**

```text
① 结构里装好了先验：局部性 + 平移等变 + 层级组合 → 小数据也能学
② 参数效率：20490 vs 101770，泛化更好
③ 可扩展性：224 能跑，1024 也能跑，参数一个不变（MLP 完全做不到）
```

**MNIST 上赢 1 个点的原因**：28×28 太简单，数字居中、笔画局部、MLP 也够。**差距要到 CIFAR-10 / 猫狗 / 缺陷检测才拉开。**

**必须用 CNN 的场景**：分辨率 > 100×100、要在图上**滑窗找东西**（缺陷/行人/病灶）、数据量小但要泛化、需要**空间定位**（检测/分割）。

**MLP 够用的场景**：28×28 小图、表格数据、特征已人工工程化。

# day6 · 感受野（4 道思考题）

## 1. 3 层 3×3 的 RF 为什么是 7 而不是 9？用"重叠"解释

**答案**：**9 是"三个窗口首尾相接、不重叠"的算法（3+3+3）。实际上相邻两个窗口重叠 2 列。**

```text
第 1 层：每个点看 3 个像素
第 2 层：把两个相邻的 3 拼起来 → 中间重叠了 2 个 → 3 + 2 = 5
第 3 层：再拼一次 → 5 + 2 = 7
```

**每多一层只向外扩 `k-1 = 2`，不是扩 `k = 3`。**

**公式视角**：`R = R + (k-1)*jump`，`jump=1` 时每层 `+2`；`1 + 2×3 = 7`。

**换个说法**：**感受野不是"把窗口加起来"，是"把窗口向外长出去的部分加起来"。**

## 2. stride=2 让 RF 从 7 涨到 15，代价是什么？用本任务数字说明

**答案**：

```text
收获：RF 7 → 15（翻倍，一个神经元看到的范围扩大一倍）
代价：空间分辨率 32×32 → 16×16 → 8×8 → 4×4
     每维只剩 1/8，总面积只剩 1/64
```

**要命的后果**：4×4 特征图上**一个格子代表原图 8×8 区域**，**3 像素宽的小缺陷在这个尺度上早就被"平均"掉了，定位精度彻底丢失**。

**一句话**：**stride 是"用分辨率换感受野"，而且是 8 倍面积地换。**

## 3. 3×3×3 省 44.9%，为什么 AlexNet 首层还用 11×11、ConvNeXt 又回去用 7×7？至少两个原因

**原因一：首层通道数少，大核根本不贵**

```text
AlexNet 首层 11×11：11*11*3*96 + 96 ≈ 34,944      （输入只有 3 通道）
3 个 3×3     ：3 * (3*3*3*96 + 96) ≈ 25,056
差距只有 1.4 倍，不是 44.9% 那种量级
```

**省 44.9% 的前提是 `C_in = C_out = 64` 这种"大通道"场景。** 首层 `C_in = 3`，`k²` 那一项基数极小。

**再加一条**：224 输入、只想要 11 的感受野，**1 层就够，省 2 次 kernel 启动 + 2 张中间特征图**（延迟敏感时更值）。

**原因二：ConvNeXt 用的是 depthwise 卷积，大核重新变便宜**

```text
普通卷积 7×7：7*7*C_in*C_out  → k² 要乘两个通道数，非常贵
depthwise 7×7：7*7*C         → k² 只乘一个通道数，贵得有限
```

**所以"大核=浪费"这条结论只在"普通卷积 + 大通道"下成立。** depthwise 让 `k²` 从"乘两次"变成"乘一次"，大核的性价比被重新定价——**这就是 ConvNeXt / MobileViT 敢用 7×7、甚至 11×11 的原因。**

**第三个原因（可选）**：大核的**有效感受野分布更均匀**（19.71% vs 35.36%），在大分辨率输入上实测精度更好。

## 4. "有效感受野只有理论的一小部分"，对缺陷检测和部署各意味着什么

**先说数字**：3 个 3×3 理论 RF 是 7×7，但**中心 3×3 就占了 35.36% 的梯度能量**；单个 7×7 只占 19.71%。

**对缺陷检测（一句）**：

> 理论 RF 算出来"够覆盖大缺陷"，但**实际权重集中在中心一小块**，**边界的大缺陷可能被"看见但没被重视"** → 所以要靠 FPN / 大核 / 注意力去真正把视野用满，不能只看公式里的 RF 数字。

**对部署（一句）**：

> **为了 RF 盲目堆层或换大核，算力全付了，但有效信息只用了中心一小块 → 性价比极低**；部署时应看"有效感受野 / 算力"这个比值，而不是只看 RF 绝对值。

**统一的一句总结**：**RF 是"理论上能看多远"，ERF 是"实际重点看哪里"。判断结构好坏要看后者，公式只给上限。**
