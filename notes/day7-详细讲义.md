## 二、BatchNorm 是什么（公式 + 手算）

**一句话**：**在一个 batch 上，对每个通道**统计均值和方差，把这一批数标准化，再用两个可学参数"还原"一点。

```text
第 1 步  μ  = 这一批在该通道上的均值
第 2 步  σ² = 这一批在该通道上的方差
第 3 步  x̂  = (x - μ) / sqrt(σ² + eps)          ← 标准化
第 4 步  y  = γ * x̂ + β                          ← γ、β 可学
```

**`eps` 只是防止除以 0**（默认 `1e-5`），不影响结果。

### 手算示范（任务 1 就是算它）

```text
x = [[1, 2],
     [3, 4],
     [5, 6],
     [7, 8]]        shape (4, 2) = 4 个样本、2 个通道
```

**通道 0 的 4 个数：1、3、5、7**

```text
μ  = (1+3+5+7)/4 = 4
σ² = ((1-4)² + (3-4)² + (5-4)² + (7-4)²)/4 = (9+1+1+9)/4 = 5
σ  = sqrt(5) ≈ 2.2361
x̂  = [(1-4)/2.2361, (3-4)/2.2361, (5-4)/2.2361, (7-4)/2.2361]
   = [-1.3416, -0.4472, 0.4472, 1.3416]
```

**通道 1（2、4、6、8）算出来一模一样**——因为它和通道 0 只差一个常数 1，均值和方差都相同。

**验算两条**：`x̂` 的 **均值 = 0**、**方差 = 1**。这两条就是"标准化"的全部含义。

**注意方向**：BN 是**按通道**做的，**不是整张图一起做**。通道 0 和通道 1 各用各的 μ、σ。

## 三、BN 里到底有几个东西（4 组量，只有 2 组可学）

这是面试必考，也是今天最容易记混的一处。

```python
bn = nn.BatchNorm1d(256)
```

**实测它的 `state_dict`（5 个 key）**：

| 名字 | 元素数 | requires_grad | 什么 |
|---|---|---|---|
| `weight`（γ） | 256 | **True** | **可学** |
| `bias`（β） | 256 | **True** | **可学** |
| `running_mean` | 256 | **False** | 统计量，滑动记录，**不学** |
| `running_var` | 256 | **False** | 统计量，**不学** |
| `num_batches_tracked` | 1 | False | 只数"跑了多少批" |

```text
可学参数：   2 × C = 512
不学但存的： 2 × C + 1 = 513
state_dict 总元素： 1025
```

**"4 组量"的准确说法**：γ、β、running_mean、running_var。**其中 γ、β 是参数（`nn.Parameter`），后两个是 buffer（注册在 `state_dict` 里但不参与梯度）。**

**为什么 γ、β 可学**：标准化会强制每层输出"均值 0 方差 1"，**这等于限制了网络表达能力**——有些层可能就想输出均值 5 的信号。**γ、β 给了"撤回标准化"的能力**，而且这个撤回的幅度由训练决定。

### running_mean 怎么更新（momentum = 0.1 实测）

```text
running_mean = (1 - momentum) * running_mean + momentum * 本批均值
```

**实测（每批均值约 100，从 0 开始）**：

| 第几批 | running_mean[0] | 本批均值 |
|---|---|---|
| 1 | **9.86** | 98.59 |
| 2 | **18.71** | 98.37 |
| 3 | **26.65** | 98.14 |
| 4 | **33.77** | 97.82 |
| 5 | **40.42** | 100.21 |

**读法**：**每次只吸收 10% 的新信息**，所以第 5 批才到 40。这是"滑动平均"，不是"取平均"。

**为什么用滑动而不是精确平均**：① 不用存所有历史；② **能适应分布变化**（老数据慢慢被忘记）。

**要多少批才接近**：`1 - 0.9^n`，**n ≈ 30 批到 96%**。这就是"跑太久 eval 才准"的原因。

## 四、BN 最要命的一点：train 和 eval 行为完全不同

**同一份输入、同一个 BN 层，两种模式给出两个不同的输出。**

### train 模式：用**当前这一批**的 μ、σ

```text
好处：不受历史影响，永远把当前这批拉成 0/1
代价：依赖 batch 大小和 batch 内容
```

### eval 模式：用**running_mean / running_var**（训练期攒下来的）

```text
好处：单个样本也能算，结果稳定、可复现
代价：如果 running stats 没攒够，结果会偏
```

**实测（同一个 4 行输入）**：

| | 输出均值 | 输出标准差 |
|---|---|---|
| train 模式 | **-0.0** | **1.0** |
| eval 模式 | **3.40** | **1.35** |

**两种模式输出最大差 = 5.20。**

**为什么 eval 是 3.40**：`running_mean` 还没有训练充分（只跑过 1 批 1000 个样本，`0.1×5 ≈ 0.5`），而输入均值是 5.06 → `(5.06-0.5)/1.35 ≈ 3.4`。**不是 bug，是"统计还没学准"。**

### 两个直接后果

**后果 1：batch = 1 时 `BatchNorm1d` 直接报错**

```text
ValueError: Expected more than 1 value per channel when training,
got input size torch.Size([1, 16])
```

**原因**：train 模式要用**这一批**算方差，**1 个样本的方差是 0**（除以 0 无意义）。

**但 `BatchNorm2d` 输入 `(1, 8, 4, 4)` 不报错**——因为它在 `N, H, W` 三个维度上统计，**1×4×4 = 16 个值**，够用。

**后果 2：batch = 2 时输出会被压成 ±1**

实测（`BatchNorm1d(16)`，输入 2 行）：

```text
[-1, -1, 1, 1, 1, ...]     均值 0.25
[ 1,  1, -1, -1, ...]     均值 -0.25
```

**每个通道里只有 2 个数，标准化后必然是"一个 -1、一个 +1"**（近似）。**这时候 BN 输出几乎不包含原始信息，只剩"谁大谁小"。**

**这就是"BN 依赖 batch，小 batch 会毁掉它"的全部含义。**

### 所以：训练完必须 `model.eval()`

```text
忘写 eval 的后果：推理时还在用"这一批"的统计
→ 同一张图，跟别的图拼成 batch 一起推理，结果会变
→ 单张推理和批量推理结果不一致（线上最难查的 bug 之一）
```

**记忆**：**`train()` 是"边学边统计"，`eval()` 是"只用学到的"。**

## 五、BN 为什么真的有用（一个硬证据）

**"BN 让前面的权重尺度失效"** —— 实测：

```text
把前一层权重整体乘 100：
  不放 BN：输出最大差异 223.91        （天翻地覆）
  放了 BN：输出最大差异 0.0001        （几乎一模一样）
```

**为什么会这样**：权重乘 100 → 输出乘 100 → μ 和 σ 也乘 100 → **标准化时分子分母同时乘 100，约掉了**。

**这条性质解释了 BN 的三个作用**：

| 作用 | 机制 |
|---|---|
| **允许大学习率** | 内部尺度不再失控，梯度不会被放大爆炸 |
| **对初始化不敏感** | 初始化小了/大了，BN 都拉回来（`0.0001` 那条就是证据） |
| **有轻微正则效果** | 每批的 μ、σ 都带噪声，等于给网络加扰动 |

**第二个作用带来的直接好处**：**你不用再小心翼翼地调初始化**（day4 那套 `kaiming` 现在不那么生死攸关了）。

### 但 BN 有它治不了的病

```text
✗ Batch 太小（< 8）→ 统计噪声大，效果反而差（检测/分割任务常见，所以有 GroupNorm、LayerNorm）
✗ 序列长度不一（RNN/Transformer）→ 用 LayerNorm，不用 BN
✗ 推理时的"训练/推理不一致"风险 → eval 忘写就出事
```

## 六、BN 放在网络的哪个位置

**标准顺序**：

```text
Conv → BN → ReLU
Linear → BN → ReLU
```

**为什么在激活前**：BN 的目的是让**激活函数的输入**分布稳定。ReLU 在 0 附近才"活着"，输入分布偏了，一半神经元直接死（day2 的死区）。**BN 先把分布拉回 0/1，ReLU 才吃得好。**

**CNN 里用 `BatchNorm2d(C)`**：实测输入 `(8, 4, 5, 5)`：

```text
输出每个通道在 (N, H, W) 上：均值 0、标准差 1
BatchNorm2d(4) 可学参数 = 8（= 2×4）
```

**一句话**：**`BatchNorm2d(C)` 的数字 = 通道数，不是 batch 数，也不是像素数。**

**参数量对比（接 day5）**：

```text
Conv2d(64, 64, 3) 参数 = 36,928
BatchNorm2d(64) 参数 = 128       ← 只有 0.35%，几乎白送
```

**这就是 BN 能被无脑加进每个卷积块的原因：几乎不花钱。**

## 七、Dropout 是什么

**一句话**：训练时**每个元素按概率 p 被随机置 0**，剩下的元素**放大 1/(1-p)**。

```text
p = 0.5 → 一半被关掉，剩下的一半数值 ×2
p = 0.3 → 30% 被关掉，剩下的 ×1/(0.7) ≈ 1.43
```

### 为什么必须放大（inverted dropout）

**实测（输入全 1，p=0.5）**：

```text
保留比例 0.502、被置 0 比例 0.498、非零值 = 2.0
```

**如果只置 0 不放大**：训练时该层输出的期望变成 `(1-p)*x`，**推理时却是 `x`** → 训练/推理尺度差 2 倍，**后面所有层的输入尺度都错**。

**放大之后**：

```text
训练期望 = (1-p) * x * 1/(1-p) = x      ← 和推理一致
实测 200 次平均 = 0.9997（理论 1.0）
```

**这就是"inverted"的含义：把缩放放在训练时做，推理时什么都不用做**（所以 `eval()` 时 Dropout 是**恒等映射**，实测输出全是 1.0）。

### 训练/推理的三种实测

| 现象 | 实测 |
|---|---|
| train：保留比例 | **0.502**（p=0.5） |
| train：非零值 | **2.0**（= 1/0.5） |
| eval：非零比例 | **1.0**（全部保留，值 1.0） |
| 同一输入连续两次 train forward | **不相同**，1000 个数里 **510 个位置不同** |

**"两次 forward 结果不同"是 Dropout 在训练时的正常现象**，不要误以为是 bug。

### Dropout 为什么能防过拟合

```text
① 每次只训练一个"随机子网络" → 相当于集成了几十个子网络，平均后更稳
② 逼网络不依赖某几个特定神经元（不能靠"那个神经元一定记得这张图"）
③ 等于往激活里加乘性噪声，和 BN 的统计噪声类似
```

**代价**：训练变慢（同样轮次效果差一点）、**eval 忘写就灾难**（推理时会随机丢信息，输出抖动）。

## 八、BN 和 Dropout 一起用：顺序与坑

**常见顺序**：

```text
Conv → BN → ReLU → Dropout
```

**为什么 BN 在前**：Dropout 置 0 会**改变这一批的方差**，BN 若放在 Dropout 之后，统计就会被随机 mask 污染（同一批数据每次 μ、σ 都不同）。

**两个真会踩的坑**：

```text
坑 1：小 batch + Dropout + BN → 方差统计特别抖，效果可能比不用还差
坑 2：现代 CNN（ResNet 之后）常在卷积块里只留 BN、把 Dropout 去掉，
      Dropout 主要留给全连接层（分类头）
```

**实践结论**：

| 场景 | BN | Dropout |
|---|---|---|
| CNN 卷积块 | **必加** | 一般不加（靠 BN 自带的正则效果） |
| 全连接分类头 | 可选 | **0.2~0.5** |
| 小数据、易过拟合 | 必加 | **必加** |
| batch < 8（检测/分割） | 换 GroupNorm | 可加 |

## 九、今天最硬的实验：BN 到底允许多大的学习率

**同一网络（784-256-128-10 MLP）、同一数据（MNIST 3000 训练 / 1000 测试）、3 轮**：

| 配置 | ep1 训练/测试 | ep2 | ep3 |
|---|---|---|---|
| noBN lr=0.05 | 0.3423 / 0.5600 | 0.5883 / 0.5740 | 0.6683 / **0.6650** |
| noBN lr=0.5 | 0.5190 / 0.6930 | 0.7940 / 0.7770 | 0.9067 / 0.8640 |
| **noBN lr=2.0** | 0.1300 / 0.1090 | 0.1087 / 0.0990 | 0.1027 / **0.1100** |
| BN lr=0.05 | 0.7883 / 0.8540 | 0.9197 / 0.8890 | 0.9520 / 0.8960 |
| BN lr=0.5 | 0.8277 / 0.8510 | 0.9423 / 0.9000 | 0.9653 / 0.9040 |
| **BN lr=2.0** | 0.7673 / 0.8220 | 0.9113 / 0.8930 | 0.9423 / **0.9090** |

**三个结论，一行一个**：

```text
① noBN + lr=2.0 → 10% 左右，等于瞎猜（完全崩了）
② BN + lr=2.0 → 90.9%，和 BN + lr=0.05 差不多（没崩）
③ 同样 lr=0.05，BN 比 noBN 高 23 个点（0.6650 → 0.8960）
```

**第 ② 条就是"BN 允许大学习率"的唯一证据，比任何解释都有说服力。**

**顺便看一个反直觉现象**：`noBN lr=0.05`（0.665）比 `noBN lr=0.5`（0.864）**更差**。不是 lr 越小越好——3 轮太少，小 lr 根本没走到。**"训练不收敛"和"训练崩掉"是两件事**（和 day2 梯度消失的区分同源）。

## 十、常见误解（这几条必须掰正）

| 误解 | 正解 |
|---|---|
| BN 是"对整张图"标准化 | **按通道**，每个通道用自己的 μ、σ |
| BN 有 4 组参数都要学 | **只有 γ、β 学**；running_mean/var 是 buffer |
| BN 在 eval 时也在算当前 batch 的均值 | **eval 用 running stats，不算当前 batch** |
| Dropout 推理时也随机丢 | **eval 是恒等映射**，全保留 |
| Dropout 训练时丢一半，输出就少一半 | 剩下的**放大 1/(1-p)**，期望不变 |
| 加了 BN 就不用管学习率了 | 是"**敢开大**"，不是"**随便开**"（开了 10 也可能崩） |
| BN 能替代 Dropout 防过拟合 | BN 的正则很弱，**过拟合明显时该加 Dropout** |
| `BatchNorm1d` 的参数是 batch size | 参数是**特征/通道数 C** |
