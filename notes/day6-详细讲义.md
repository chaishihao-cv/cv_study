## 二、感受野的定义（一句话 + 一个动作）

**定义**：

> 输出特征图上的**一个**点，是输入图上一个多大范围内的像素**共同算出来的**。这个范围就是感受野（RF）。

**验证它的动作**（今天全靠这一招）：

```
输入 → 一路卷积 → 取输出中心那一个点 → 反向求导
→ 看输入图上哪些像素的梯度非 0 → 那一块就是感受野
```

**为什么梯度能测感受野**：输出那一个点只由感受野内的输入算出来，所以只有那些输入的梯度不为 0；范围内的输入，梯度必为 0。

**第一次先把单层看懂**：

```
输入 5×5，核 3×3，stride 1，无 padding
输出 3×3

输出左上角那个点 ← 只看输入的左上 3×3
输出中间那个点   ← 只看输入的中间 3×3
```

**单层 k×k 的感受野 = k。** 3×3 → 3，7×7 → 7，1×1 → 1（这是 1×1 卷积的定义：只看一个像素，跨通道混信息）。

**记住这条：感受野不是"输出尺寸"，是"往回看多远"。day5 算的是输出多大，今天算的是看回去多宽。**

## 三、单层与两层：先手推两层

**一层 k=3**：RF = **3**

**两层 k=3**：第二层的一个点 ← 第一层的 3 个点 ← 输入的 5 个点

```text
输入 :  a b c d e
第1层:   [x] 三窗口1 → a,b,c
         [y] 三窗口2 → b,c,d
         [z] 三窗口3 → c,d,e
第2层:  只看 x,y,z → 覆盖 a~e = 5 个
```

**所以两层 3×3 的 RF = 5。**

**三层呢？** 第二层的 3 个点每个覆盖 5 个，向右错开 1 个像素：

```text
第2层点1 → 覆盖 1~5
第2层点2 → 覆盖 2~6
第2层点3 → 覆盖 3~7
合并 → 1~7 = 7 个
```

**三层 3×3 的 RF = 7。规律出来了：s=1 时，每加一层 3×3，感受野 +2。**

## 四、通用公式（必须背下来，考试和工作都用）

```text
R(本层) = R(上一层) + (k - 1) * jump
jump    = jump * s          （每过一层，把 jump 乘上本层 stride）
初始：R = 1, jump = 1
```

**为什么要 jump 这个东西**：因为它记录"这一层的 1 个像素，在输入图上跨了几格"。stride=1 时 jump 一直是 1（逐格走），一旦用了 stride=2，jump 就变成 2、4、8……感受野长得飞快。

**三条必背结论**：

| 配置 | 感受野怎么变 | 数字验证 |
|---|---|---|
| k=3, s=1 逐层堆 | 每层 **+2** | 1→3、2→5、3→7、5→11、10→21 |
| 中间夹 s=2 | 每层**翻倍式**跳 | 3 层 s=2 → **3、7、15** |
| 有 pooling s=2 | 相当于 k=2,s=2 的一层，**+jump** | 见下面链式手算 |

### 手算一条真实链路（今天第一个重点）

配置：`conv1(3,s1) → conv2(3,s1) → pool1(2,s2) → conv3(3,s1) → conv4(3,s1) → pool2(2,s2) → conv5(3,s1)`

| 层 | k | s | R | jump |
|---|---|---|---|---|
| 起点 | — | — | 1 | 1 |
| conv1 | 3 | 1 | **3** | 1 |
| conv2 | 3 | 1 | **5** | 1 |
| pool1 | 2 | 2 | **6** | 2 |
| conv3 | 3 | 1 | **10** | 2 |
| conv4 | 3 | 1 | **14** | 2 |
| pool2 | 2 | 2 | **16** | 4 |
| conv5 | 3 | 1 | **24** | 4 |

**实测核对：`conv(3,s1) + conv(3,s1) + pool(2,s2) + conv(3,s1)` 的 RF 实测 = 10 像素，手算 = 10，完全一致。**

注意 pool 那一步：**`+ (2-1)*1 = +1`**（第一层 pooling 时 jump 还是 1，所以只加 1，不是加 2）。**这是最容易算错的一格。**

## 五、用梯度法自己实测（今天的核心动作）

**原理**：`out[0,0,c,c].backward()` → 只有感受野内的输入像素拿到梯度。

**代码骨架（任务 2 就是把这段补完）**：

```python
x = torch.randn(1, 1, 64, 64, requires_grad=True)
out = net(x)
r = c = out.shape[-1] // 2          # 取输出正中心那一个点
out[0, 0, r, c].backward()          # 反向，把梯度传回输入
g = (x.grad[0, 0].abs() > 1e-12)     # 非 0 的位置 = 感受野
idx = g.nonzero()
rf = idx[:, 0].max() - idx[:, 0].min() + 1
print(rf)
```

### 实测结果（我已经跑过，你跑出来应该一样）

| 层数（3×3, p=1, s=1） | 实测 RF | 公式 1 + 2L |
|---|---|---|
| 1 | 3×3 | 3 |
| 2 | 5×5 | 5 |
| 3 | 7×7 | 7 |
| 4 | 9×9 | 9 |
| 5 | 11×11 | 11 |
| 10 | 21×21 | 21 |
| 20 | 41×41 | 41 |

**"20 层才看得到 41 像素"—— 这就是今天最重要的一个打击。**

**再看 stride 的威力**（k=3, p=1, s=2）：

| 层数 | 实测 RF |
|---|---|
| 1 | 3 |
| 2 | **7** |
| 3 | **15** |

**同样 3 层，stride=1 只能看到 7，stride=2 看到 15。翻倍。**

**代价也马上能算**：输入 32×32 走三层 s=2 → `32 → 16 → 8 → 4`。**看得远了，但图从 32 缩到 4，空间精细度没了。**

> **记住这对矛盾：感受野 ↑ 和 空间分辨率 ↓ 是同时发生的。** 后面所有网络结构（FPN、UNet、dilated conv）都在解这个矛盾。

## 六、"3 个 3×3 = 1 个 7×7"——三个层面分别是什么

这句话到处都在传，但**它其实是三个不同的命题**，混在一起就容易答错。

### 层面 1：感受野相同（这是真的）

```
3 个 3×3 堆叠        RF = 7
1 个 7×7             RF = 7
```
**实测：3×3×3 → 7×7；7×7 → 7×7。相同。**

### 层面 2：参数量和计算量更省（这也是真的）

C_in = C_out = 64 时：

| 方案 | 参数 | MACs（224×224 输入） |
|---|---|---|
| 1 个 7×7 | **200,768** | **10,070,523,904** |
| 3 个 3×3 | **110,784** | **5,549,064,192** |
| 1 个 5×5 | 102,464 | 5,138,022,400 |

**参数和计算量都省 44.9%**（比值 1.8148）。**注意：参数和 MACs 省的比例一模一样，因为两者都是 k² 的倍数。**

推导很简单：

```
7×7：  49 * C * C
3×3×3：3 * 9 * C * C = 27 * C * C
49 / 27 = 1.8148        →  省 44.9%
```

### 层面 3：能不能"完全等价"（这里要诚实：只有内部等价）

**我在实测里把三个 3×3 核做 full 卷积，合成出一个 7×7 核**，然后用堆叠网络和单层大核网络在同一张图上比：

```
内部区域（离边界 ≥3 像素）最大差异 : 3.052e-05    ← 数值上是同一个东西（float32 噪声）
整体最大差异                       : 38.88
边界行最大差异                     : 34.56          ← 差了 30 多！完全不等价
```

**为什么边界不等价**：3 层网络在边界上加了 3 次 padding（补的是 0），而 1 层大核只补 1 次。**padding 的次数不一样，边界行为就不一样。**

> **所以准确说法是**：**3 个 3×3 在内部等价于 1 个 7×7（核是可合成出来的），但边界不等价；而且中间可以插非线性，表达力比单个大核更强。**
>
> 面试说"3 个 3×3 = 1 个 7×7"时，最好补一句"**是感受野和参数量层面等价，严格来说是内部线性等价**"，这一句就把你和背结论的人分开了。

## 七、既然 3×3 更便宜，为什么还有大核

四个真实原因，别只会说"3×3 更好"：

1. **大核一次算完，层数少 → 延迟低**。3 个 3×3 要做 3 次 kernel launch、3 次读写内存；在**小图**或**浅层**上，一次 7×7 反而更快。
2. **浅层用大核更划算**。第一层输入通道少（3 通道），`7×7×3×64` 的参数量才 9,408；而堆 3 层要在 64 通道上反复算。
3. **现代网络又回到大核**。ConvNeXt 用 7×7 depthwise，RepLKNet 用 31×31——**因为 depthwise 卷积让 k² 只乘 1，不再乘 C_in×C_out，大核突然变便宜了**。
4. **有效感受野（ERF）不等于理论感受野**。堆叠小核的梯度能量更集中在中心：

| 结构 | 中心 3×3 占总梯度比例（30 次随机初始化统计） |
|---|---|
| 3 个 3×3 | **35.36%**（标准差 8.62） |
| 1 个 7×7 | **19.71%**（标准差 3.24） |

**意思是**：3 层 3×3 理论上看到 7×7，但**实际"重点看"的是中心 3×3 那一圈**（占三分之一能量）；单个 7×7 的能量分布更均匀。

> **这叫"有效感受野远小于理论感受野"**，是 2017 年一篇论文的核心发现。**它解释了为什么"理论 RF 212"的 VGG 依然抓不住整体语义。**

## 八、放到真实网络里看：数字会吓你一跳

### 1. VGG16 的感受野

VGG16 = 13 个 3×3 + 5 个 2×2 池化。用 H4 的公式逐层算：

| 阶段 | 累计 RF |
|---|---|
| conv1_2 后 | 5 |
| pool1 后 | 6 |
| conv2_2 后 | 14 |
| pool2 后 | 16 |
| conv3_3 后 | 40 |
| pool3 后 | 44 |
| conv4_3 后 | 92 |
| pool4 后 | 100 |
| **conv5_3 后** | **196** |
| **pool5 后** | **212** |

**输入 224×224，理论 RF 212 —— 差 12 像素没覆盖到。**

**但注意**：pool5 之后输出只有 7×7，那 7×7 的每个点各自覆盖 212 个像素，**整个 7×7 摊开就把 224 全覆盖了**。这就是分类网络"看得见全图"的真实机制：**不是靠单个神经元，是靠整张特征图的拼接。**

### 2. 一个残酷的对照

```
想只靠单条 3×3 链覆盖 224 像素：
  需要 (224 - 1) / 2 = 111.5 → 112 层
  参数代价：112 * 9 * C * C，且 stride=1 时特征图一直是 224×224，显存撑不住
```

**所以真实网络没有一个这么干的，全部靠 stride / pooling 来"便宜地"扩大 RF。**

### 3. 这跟你的两个目标岗位有什么关系

**缺陷检测**：
- 缺陷可能很大（一条 200 像素的划痕）→ **检测头必须有足够大的 RF**，否则只能看到划痕中间一段，判成"局部纹理异常"漏检。
- 缺陷也可能很小（3 像素的点）→ **需要高分辨率特征图**，不能全靠 stride 下采样。
- **这两个需求打架** → 所以有 FPN（多尺度）、UNet（skip connection）。**day20 讲 UNet 时你会回头看今天。**

**部署**：
- 大 RF 通常意味着"更深的网络 + 更多的 stride"
- **改成 stride=1 提精度 → 特征图变大 → 显存和延迟爆炸**
- 客户问"能不能提精度又不掉帧"时，你要知道**这个矛盾是有物理下限的**

## 九、五个必须分清的概念（今天最容易搞混）

| 概念 | 问的是什么 | 例子 |
|---|---|---|
| **输出尺寸**（day5） | 出来的图多大 | `(224+2-3)/1+1 = 224` |
| **感受野**（今天） | 往回看多远 | 3 层 3×3 → 7 |
| **有效感受野** | 实际重点看多大 | 3×3×3 中心 3×3 占 35% |
| **参数量**（day5） | 有多少个可学的数 | 1792 |
| **MACs / FLOPs**（day5） | 算多少次 | 86,704,128 |

**四个数字经常被混成"网络复杂度"一个词，面试时能分开说，就是专业度。**

### 还要分清：dilation（空洞卷积）

```
3×3, dilation=2  →  实测 RF = 5，参数量 = 9
```

**一个 3×3 的核，参数不变，感受野当 5×5 用。** 这就是第 8 节说的"解矛盾"的第三个工具（不用 stride 也能扩 RF，还保住分辨率）。

> **补充一句**：`k_eff = k + (k-1)*(d-1)`。d=2, k=3 → 3+2 = 5。**这个公式和 H4 的递推公式配合用。**

## 十、常见误解清单（我见过的错误说法）

| 错误说法 | 正确说法 |
|---|---|
| "3 层 3×3 的感受野是 9" | 是 **7**。每层 +2，不是 +3（重叠部分不能重复算） |
| "感受野 = 输出尺寸的倒数" | 无关。输出尺寸是步长决定的，感受野是核和 jump 决定的 |
| "stride 不影响感受野" | **影响最大**。s=2 让 jump 翻倍，RF 指数式增长 |
| "感受野越大越好" | 越大越丢空间精度，小目标反而检不到；**要匹配目标尺度** |
| "3 个 3×3 完全等价 1 个 7×7" | 内部线性等价，**边界不等价**（padding 次数不同），且可插非线性 |
| "VGG 理论 RF 212，所以能看见全图" | 单个神经元只 212；**整张 7×7 特征图才覆盖全图** |

### 今天踩的坑（我的）

1. **第一版实测脚本把梯度转成布尔掩码再归一化**，结果 7×7 里 49 个格子全是 2.0%（=1/49），看起来"能量完全均匀"——**那是布尔值 1 除 49，不是真梯度**。教训：**统计前先确认拿的是数值还是掩码**。
2. **VGG16 一开始只算了 4 个池化，算出 196**。漏了 pool5。**加回 pool5 才是 212**。教训：**数层数必须对着结构图数，不能凭记忆**。
3. 链式网络手算时，pool 那一步 `+ (2-1)*jump`，我第一遍写成 +2，**结果差 1 像素**。教训：**pool 也是 k=2 的"卷积"，公式照套，不许凭直觉**。
