## 0. 这一课在整条路线里的位置

后面几十天要学的东西（CNN、YOLO、U-Net、Transformer），拆开看都是同一个流程：

```
数据 → 模型算预测 → 和答案比算损失 → 求梯度 → 改参数 → 重复
```

今天用**只有 2 个参数**的模型，把这个流程完整走一遍。参数从 2 个变成 200 万个时，算法一模一样，变的只是"求梯度的方式"（从手推公式变成自动求导）。

**所以今天不是学"拟合直线"，是学训练流程的骨架。**

## 1. 问题的起点：机器怎么"猜"出一条直线

假设你是老板，手上有 100 个测量点，想知道背后的规律。

你看到这些点大致沿一条线分布，于是提出一个假设：

```
y = w*x + b
```

- `w` 叫斜率（权重）
- `b` 叫截距（偏置）

问题是：**w 和 b 到底等于多少？** 肉眼能猜个大概（斜着往上、截距 3 左右），但猜不准，更猜不出 2.03 还是 1.97。

**机器学习要做的事就是：让程序自己去试，一步步逼近正确答案。**

---

## 2. 五个必须分清的角色

这是理解一切训练任务的基础框架，先背下来。

| 角色      | 是什么             | 今天的具体例子            |
| ------- | --------------- | ------------------ |
| **数据**  | 已知的输入和答案        | 100 个 `(x, y)` 点   |
| **模型**  | 负责算预测的公式        | `y_pred = w*x + b` |
| **参数**  | 模型里待定的数字，训练就是改它 | `w` 和 `b`          |
| **损失**  | 一个数字，衡量"错得多离谱"  | MSE                |
| **优化器** | 决定怎么改参数的规则      | 梯度下降               |

**关键区分：参数 vs 超参数**

|     | 谁来决定             | 例子                                |
| --- | ---------------- | --------------------------------- |
| 参数  | **程序自己学**（靠梯度更新） | `w`、`b`、卷积核权重                     |
| 超参数 | **人来设定**         | 学习率 `lr`、训练轮数 `epochs`、batch size |

初学者最常见的混乱是把学习率当成"也会自己学的东西"。它不会，**得你手动调**——这就是为什么调参是件苦力活。

## 3. 损失函数：为什么用平方，不用绝对值

### 3.1 先定义

```
L = (1/n) Σ (y_pred_i - y_i)²
```

读法：把每个点的"预测减真实"求平方，全部加起来，再除以个数。

### 3.2 为什么不直接相加（不取绝对值）

假设有两个点，误差分别是 +2 和 -2：

| 方案   | 计算              | 结果    | 问题                     |
| ---- | --------------- | ----- | ---------------------- |
| 直接相加 | (+2) + (-2)     | **0** | 明明错了 4 个单位，却算出"完美"     |
| 绝对值  | \|+2\| + \|-2\| | 4     | 正确，但绝对值在 0 点不可导，优化时不好用 |
| 平方   | 4 + 4           | 8     | 正确，且处处可导               |

**平方同时解决了两个问题**：正负误差不抵消；函数光滑可导。

### 3.3 平方的副作用：对离群点特别敏感

误差从 2 变成 4（翻倍），平方后从 4 变成 16（**四倍**）。

所以 MSE 训练出的模型会"优先照顾误差大的点"，一个标注错的数据就能把模型带偏。这也是为什么工业界有另一套损失（MAE、Huber、Focal Loss）——**没有万能损失，只有适合任务的损失**。

### 3.4 一个能直接看懂的结论：loss 有"地板"

数据里带了标准差 0.3 的高斯噪声。

即使你完美找到了 `w=2, b=3`，预测和真实之间**仍然差一个噪声**，因为噪声是随机的，谁都预测不出来。

那 loss 会是多少？

```
噪声方差 ≈ 0.3² = 0.09
```

所以 **loss 的理论下限约等于 0.09，不可能降到 0**。

我们实测最终 loss 是 **0.0733**，比 0.09 还低一点点，是因为这 100 个样本恰好"运气好"（样本方差略小于理论方差）。

> **这条极其重要**：以后你看到 loss 卡在某个值降不下去，先算一下"数据本身的噪声有多大"，很多时候不是模型不行，而是**你已经触到了天花板**。

顺推一下：如果把噪声放大到 0.9，那 `0.9² = 0.81`，loss 会停在 0.8 左右——而 `w`、`b` 依然会学准，因为噪声均值为 0，平均之后自己抵消了。

## 4. 梯度到底是什么

### 4.1 一维直觉

想象一个山谷地形，横轴是 `w`，纵轴是 loss：

```
loss
  ↑
  │＼
  │  ＼
  │    ＼
  │      ＼
  │        ＼___／  ← 谷底（loss 最小）
  └──────────────→ w
       1.0   2.0
```

- 你在 w=0 处，脚下是**陡坡**
- 梯度 = 这个点的**坡度**
- 坡度指向"上升最快"的方向
- 想下山，就**往坡度的反方向走**（所以更新公式是减号）

### 4.2 梯度是负数意味着什么

以 `w=0.37, b=1.25` 这组参数为例，我们算出的 `∂L/∂w = -1.12`。

负梯度 = "w 增大的方向是下坡方向"。于是：

```
w_new = w - lr*(∂L/∂w) = 0.37 - 0.1*(-1.12) = 0.37 + 0.112 = 0.482
```

w 变大，往 2.0 靠近了。**减号不是口诀，是数学：负梯度代表下坡方向。**

### 4.3 多参数时梯度是什么

参数变成 200 万个时，"坡度"变成一个 200 万维的向量，每一维是 loss 对该参数的偏导。

**每个参数各自有自己的坡度，各走各的**——这就是为什么更新要写成 `w = w - lr * grad_w`，而不是一个全局的数。

## 5. 完整推导（这一课最重要的一段）

### 5.1 把目标写清楚

```
L(w, b) = (1/n) Σ (w*x_i + b - y_i)²
```

要求：`∂L/∂w` 和 `∂L/∂b`。

### 5.2 拆成两层（链式法则）

令内部项

```
u_i = w*x_i + b - y_i
```

则 `L = (1/n) Σ u_i²`。现在求导要分两层：

**第一层：平方的导数**

```
d(u²)/du = 2u
```

（这是高中数学公式，`(x²)' = 2x`，把 x 换成 u 而已）

**第二层：u 对 w 的导数**

```
u_i = w*x_i + b - y_i
```

对 w 求导时：

- `w*x_i` 的导数是 `x_i`（w 的系数就是 x_i）
- `b` 不含 w，导数是 0
- `y_i` 是常数，导数是 0

所以

```
∂u_i/∂w = x_i
```

### 5.3 两层相乘（链式法则）

```
∂L/∂w = (1/n) Σ [ 2u_i * (∂u_i/∂w) ]
      = (1/n) Σ [ 2*(w*x_i + b - y_i) * x_i ]
```

把符号换回代码里的名字（`y_pred_i = w*x_i + b`）：

```
∂L/∂w = mean( 2*(y_pred - y)*x )
```

**这一步就是你代码里 `grad_w = np.mean(2*(y_pred-y)*x)` 的全部来历。**

### 5.4 顺手推 b

`∂u_i/∂b = 1`（b 的系数是 1），所以

```
∂L/∂b = (1/n) Σ 2*u_i*1 = mean( 2*(y_pred - y) )
```

### 5.5 两个公式只差一个 x

|       | 公式                     | 差在哪     |
| ----- | ---------------------- | ------- |
| ∂L/∂w | `mean( 2*(pred-y)*x )` | 多乘了 `x` |
| ∂L/∂b | `mean( 2*(pred-y) )`   | 没有 x    |

**为什么？** 因为 x 是 w 的系数——"w 对输出的影响力"有多大，取决于 x 有多大。x=0 时，w 怎么变都不影响预测，梯度自然是 0。

### 5.6 用数值验证一次（别只信推导）

把 w 加一点点 h，看 loss 变化多少，和公式算的对比：

```
解析梯度 dL/dw = -1.12269145
数值梯度 dL/dw = -1.12269145
误差 = 2.08e-10
```

误差在浮点精度级别，说明公式正确。这个手法叫 **gradient check**，PyTorch 里有对应 API，自定义层上线前都要跑一遍。

## 6. 学习率：三种形态，不改代码看不出来

### 6.1 三种形态对照

| lr   | 曲线形状                    | 参数结果                                   | 判定           |
| ---- | ----------------------- | -------------------------------------- | ------------ |
| 0.01 | 缓慢下降，200 轮还没变平          | w=1.505（真值 2.0）                        | **没收敛**（步太小） |
| 0.1  | 前 30 轮陡降，之后变平           | w=2.021，b=2.969                        | **正常收敛**     |
| 1.5  | 前 40 轮像平的，第 45 轮直冲 1e30 | b=-3.34e15 | **发散**（步太大）  |

### 6.2 为什么"太大"会导致爆炸，而不是来回晃

以 b 的更新为例，可以整理成：

```
b_new ≈ b_old × (1 - 2*lr)
```

代入 lr=1.5：

```
系数 = 1 - 3 = -2
```

**每一轮 b 的绝对值翻倍、符号翻转。** 50 轮就是 `2^50 ≈ 1e15`。

我们实测 `b = -3342623485249895`，正好是 2^51 量级，和理论推算吻合。

**所以"发散"的本质是：每轮误差按固定倍数放大，指数增长。** 在线性坐标上看，指数增长就是"一直很平，然后突然变竖线"。

### 6.3 稳定条件

| 参数  | 稳定要求        | 原因                               |
| --- | ----------- | -------------------------------- |
| b   | `lr < 1`    | 系数 `1-2lr` 的绝对值必须小于 1            |
| w   | `lr < 3` 左右 | 系数 `1-2*lr*E[x²]`，而 `E[x²]≈0.33` |

lr=1.5 时：对 b 已超限（发散），对 w 还在安全区。

**这解释了一个奇怪现象**：你那张发散图里 `w = 1.57` 一直没动，只有 b 炸了。

原因有两条：

1. b 单方面爆炸，w 本身还在稳定区
2. 我们的 x 关于 0 对称（`mean(x)=0`），所以 b 的爆炸通过 `x` 传导到 w 的部分**相互抵消**了

> 这就是为什么"看懂公式"和"会调参"是两件事——**不同参数的敏感度不一样**。

### 6.4 为什么发散图前半段看起来没变化

loss 最大值 3e30，正常的 loss 是 0.07～10，相差 29 个数量级，同一根线性坐标轴上，前面自然被压成贴地直线。

```python
ax.set_yscale("log")   # 加这一行才看得清"先降后爆"
```

## 6.5 为什么学习率不改变最终答案（最小二乘闭式解）

前面说"lr=0.1 正常收敛"，那**收敛到哪**？这个终点能不能提前算出来？

能。而且这是本课最有价值的一条认识：**学习率只影响"多快到"，不影响"到哪"**。

### 6.5.1 令梯度等于 0，就能解出答案

损失最小的地方，梯度必然是 0。把第 5 节的两个梯度公式设成 0：

```
∂L/∂w = 0  →  w*mean(x²) + b*mean(x) = mean(x*y)
∂L/∂b = 0  →  w*mean(x)  + b         = mean(y)
```

这就是一个二元一次方程组。对一般的数据解出来：

```
w* = [mean(x*y) - mean(x)*mean(y)] / [mean(x²) - mean(x)²]
b* = mean(y) - w*mean(x)
```

**这叫最小二乘闭式解**——不用迭代，直接算出最优参数。

本课的数据 `mean(x) ≈ 0`，所以公式简化成极其好记的两条：

```
b* = mean(y)
w* = mean(x*y) / mean(x²)
```

### 6.5.2 实测：给定这批数据，答案唯一确定

同样 100 个点、`x` 在 [-1,1]、seed=42，只改噪声：

| 噪声 σ | 最优 w* | 最优 b* | 最低 loss* |
|---|---|---|---|
| 0.2 | 1.9580 | 2.9899 | 0.0233 |
| 0.3 | 1.9371 | 2.9849 | 0.0524 |
| 0.9 | **1.8112** | 2.9548 | **0.4716** |

### 6.5.3 梯度下降 vs 闭式解：完全一致

| 设置 | 实际跑出来 | 闭式解 | 差异 |
|---|---|---|---|
| lr=0.10，200 轮 | w=1.9371 b=2.9849 | w=1.9371 b=2.9849 | **0.000001** |
| lr=0.05，200 轮 | w=1.9352 b=2.9849 | w=1.9371 b=2.9849 | 0.002（还没完全到） |
| lr=0.10，300 轮 | w=1.9371 b=2.9849 | 同上 | 0（已到顶） |
| 噪声 0.9，200 轮 | w=1.8112 b=2.9548 | w=1.8112 b=2.9548 | 0 |

**学习率减半，终点不变；轮数加倍，终点也不变。** 原因是 L 是凸函数（一个碗），碗只有最低的一个点，走多快都只能走到那里。

### 6.5.4 由此得到三条判断规律

| 改动 | 是否改变最终答案 | 该怎么判断 |
|---|---|---|
| 调学习率 | ❌ 只改速度 | 收敛了就都一样 |
| 加训练轮数 | ❌ 收敛后无意义 | 看曲线是否已变平，平了就停 |
| **改数据（噪声/样本）** | ✅ 答案跟着变 | 这才是唯一能改变终点的操作 |

**所以调参时的正确顺序是：先看数据有没有问题，再动超参数。** 拿着坏数据猛调 lr，只是在更快地到达一个错误的终点。

### 6.5.5 关于"噪声越大，w 越不准"的原因

噪声 0.3 → 0.9 时，`w*` 从 1.937 掉到 1.811，而 `b*` 几乎不动（2.985 → 2.955）。

原因是：噪声会和 x 偶然产生"虚假相关"（`mean(noise*x) ≠ 0`），这一部分被误当成斜率吃掉了。**噪声越大，这次抽样造成的斜率偏差越大。** 而 `b` 只和 `mean(noise)` 有关，平均之后接近 0，所以稳。

> 一句话：**样本有限时，斜率和截距的抗噪能力不同**，这也是为什么真实项目要靠更多数据、更强的正则化，而不是靠调学习率。

### 6.5.6 地板 ≈ 噪声的"样本方差"，不是理论方差

理论 `σ²`：0.3 对应 0.09，0.9 对应 0.81。但实测最低 loss 是 0.0524 和 0.4716——都明显低于理论值。

原因是：**地板等于这批数据中噪声的"实际方差"**，而 100 个点上算出的样本方差本身会偏离理论值（这批样本恰好"运气好"）。

实测对照：

```
噪声实际方差 = 0.0537
最优 loss   = 0.0524      ← 几乎相等
```

**这条在看真实项目的 loss 曲线时非常有用**：loss 卡住不动时，先估算数据的噪声水平，很可能不是模型不行，而是已经到顶了。

## 7. 为什么用 mean，不用 sum

代码里 `np.mean(2*(pred-y)*x)`，如果换成 `np.sum(...)`：

- n=100 时，梯度是原来的 **100 倍**
- 等价于把学习率偷偷放大了 100 倍
- 结果：直接爆炸

**用 mean 让梯度量级与样本数无关。** 这样 batch_size 从 8 改到 64，学习率不用跟着改，训练才可控。

工程上这是常识：**损失函数的"平均"约定，不是数学偏好，是数值稳定的要求。**

## 8. 代码逐行讲解

```python
np.random.seed(42)          # 固定随机种子：每次跑生成的噪声一样，实验才能对比
```

```python
x = np.linspace(-1, 1, 100)          # 100 个均匀分布的点，shape (100,)
noise = np.random.randn(100) * 0.3   # 标准正态 × 0.3，模拟真实测量的抖动
y = 2.0*x + 3.0 + noise              # 真值 + 噪声 = 我们看到的"标签"
```

```python
w, b = 0.0, 0.0     # 从 0 开始，故意让它什么都不知道
loss_history = []   # 每轮 loss 存起来，最后画曲线
```

```python
for epoch in range(epochs):
    y_pred = w*x + b                 # 前向：这一步产生 shape (100,) 的预测
    loss = np.mean((y_pred-y)**2)    # 损失：一个标量
    loss_history.append(loss)
    grad_w = np.mean(2*(y_pred-y)*x) # 梯度：注意这里用的是"更新前"的预测
    grad_b = np.mean(2*(y_pred-y))
    w = w - lr*grad_w                # 更新
    b = b - lr*grad_b
```

**⚠️ 关键细节：梯度和更新必须在同一个循环迭代里、用同一批参数算出来。**

常见错误：

```python
# 错误写法：先更新 w，再用新的 w 算 b 的梯度
w = w - lr*grad_w
grad_b = np.mean(2*(w*x+b-y))   # 用的是新 w，理论上应该是旧 w
```

单看影响不大，但参数多、步长大时会放大误差。**标准做法是：所有梯度先算完，再统一更新。**

## 9. 训练集 / 验证集 / 测试集

### 9.1 为什么必须分开

模型会"记住"见过的数据。如果拿训练过的数据去评估，等于**开着答案考试**，分数没有意义。

| 集合  | 类比    | 用途               | 能用几次   |
| --- | ----- | ---------------- | ------ |
| 训练集 | 平时练习题 | 更新参数             | 反复     |
| 验证集 | 模拟考   | 调超参数、判断过拟合、决定何时停 | 反复     |
| 测试集 | 高考    | 最终评估             | **一次** |

### 9.2 常见误用

1. **用测试集调参** —— 调完再报测试分数，这个分数已经"污染"了，虚高
2. **验证集和测试集混着用** —— 两者职责不同：验证集给你做决策，测试集只报告结果
3. **数据泄漏** —— 隔壁帧图像同时出现在训练和验证集（视频任务高发），分数虚高得离谱

### 9.3 今天的任务为什么不需要划分

因为只有 2 个参数、100 个点，而且我们知道真值（2 和 3），直接用真值判断学得准不准。

**参数越多、数据越少，验证集越重要。** 到 day8 猫狗分类，你就能亲眼看到 val_loss 拐头向上——那就是过拟合的现场。

## 10. MSE 与交叉熵：分工不同

### 10.1 MSE：管"数值"

```
MSE = mean((预测 - 真实)²)
```

适用：预测**连续数值**——房价、温度、坐标、图像像素。

### 10.2 交叉熵：管"概率"

分类任务输出的是"属于各类的概率"，比如 `[0.9, 0.1]` 表示 90% 是猫。

```
交叉熵 = -Σ y_true * log(y_pred)
```

直觉：模型说"99% 是猫"，结果不是猫，`log(0.01)` 是个很大的负数，乘 -1 后变成巨大的惩罚。

**所以交叉熵的核心特性是：对"自信地答错"惩罚极重。** 这正是分类任务想要的——宁可谨慎，不要瞎自信。

### 10.3 一句话分工

| 任务类型 | 输出       | 损失                |
| ---- | -------- | ----------------- |
| 回归   | 一个连续数值   | MSE / MAE / Huber |
| 分类   | 各类概率     | 交叉熵               |
| 目标检测 | 框坐标 + 类别 | 两者混合（day14 讲）     |

## 11. 常见报错与排查

| 现象                                            | 大概率原因                          | 怎么办                 |
| --------------------------------------------- | ------------------------------ | ------------------- |
| `ValueError: Invalid format specifier '.4f '` | f-string 里 `f` 后多了空格           | 改成 `{loss:.4f}`     |
| loss 变 `inf` / `NaN` / 1e20                   | 学习率太大                          | lr 除以 10 再试         |
| loss 完全不降                                     | 忘了 `np.mean`（求和导致梯度巨大）/ 减号写成加号 | 检查这两处               |
| loss 降得很慢                                     | 学习率太小，或轮数不够                    | 加大 lr 或加 epochs     |
| 曲线看起来是平的                                      | 跨多个数量级，线性坐标看不清                 | `set_yscale("log")` |
| 训练后参数是天文数字                                    | 已发散，前面的训练全废                    | 缩小 lr 从头训           |

**排查顺序铁律**：**先怀疑学习率 → 再怀疑数据 → 最后才怀疑模型结构。** 90% 的"模型不收敛"都是前两个原因。

## 12. 五句话总结本课

1. 训练 = **预测 → 算损失 → 求梯度 → 改参数**，循环往复
2. 梯度是损失的坡度，**负梯度指向下坡**，所以更新用减号
3. 对 w 的梯度比 b 多乘一个 x，因为 x 是 w 的系数
4. 学习率决定步长：**太小不收敛，太大会指数级爆炸**
5. loss 有"地板"（约等于噪声方差），**降不到 0 不代表模型有问题**
