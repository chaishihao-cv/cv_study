## 二、感受野是什么（定义要能一句话说）

> **输出特征图上的一个点，是输入图上一个多大范围内的像素共同算出来的。这个范围就是感受野（RF）。**

**和 day5 的"输出尺寸"必须分开**：

| 问什么 | 公式 | 例子 |
|---|---|---|
| 输出尺寸（day5） | `(H + 2p - k)/s + 1` | 224 → 224 |
| **感受野（今天）** | `R = R + (k-1)*jump` | 3 层 3×3 → 7 |

**一个是"出来多大"，一个是"往回看多远"。**

**为什么必须懂它**：卷积是局部的（一层 3×3 只看 3×3），**网络要理解"整张图里有什么"，只能靠堆层把视野撑开**。所以"这个网络能不能看到足够大的目标"是判断结构合不合理的硬指标。

## 三、通用公式与三条结论（今天第一重点）

```text
R(本层) = R(上一层) + (k - 1) * jump
jump    = jump * s           （每过一层，把 jump 乘上本层 stride）
初始：R = 1, jump = 1
```

**"用 jump 算 R，再用 s 更新 jump"——顺序不能反。**

| 配置 | 规律 | 实测 |
|---|---|---|
| k=3, s=1 逐层 | 每层 **+2** | 3、5、7、9、11、21（10 层）、41（20 层） |
| 中间夹 s=2 | 每层**翻倍式**涨 | 3、7、15 |
| 池化 k=2, s=2 | 加 **jump**（不是 +2） | 5 → 6（jump 从 1 变 2） |

**两条口诀**：

```text
k=3、s=1 堆 n 层  →  R = 1 + 2n
1 层→3   2 层→5   3 层→7   20 层→41
```

## 四、三个最常问的细节

### 1. padding 为什么不参与感受野计算

**`p` 只影响输出尺寸，不影响一个神经元看到的输入像素数量。** 它是在边界补 0，不是"多给了内容"。

**所以看到 `p=1` 在 RF 公式里直接跳过。**（但它影响"边界行为"，见第八节）

### 2. `s=2` 的第一层，感受野还是 3

**起点永远是 `R=1, jump=1`，跟 s 无关。** 因为 jump 是"用完才乘 s"：

| 层 | k | s | R | jump |
|---|---|---|---|---|
| 起点 | — | — | **1** | **1** |
| conv3 | 3 | 2 | **3** | 2 |
| conv3 | 3 | 2 | **7** | 4 |
| conv3 | 3 | 2 | **15** | 8 |

**直觉**：第一层的窗口永远连着盖住 3 个像素；**s 变的是"相邻两人站得多开"，要到第二层把几个人凑起来时才体现**——所以 s 的影响**延迟一层**。

### 3. 池化那一步是 `+(k-1)*jump`，k=2 所以只加 1

```text
pool2(s2)： (2-1)*jump = +jump
第一层 pooling 时 jump=1 → 只 +1
```

**看到 "2×2" 就加 2 是今天最大的坑。** 正确算法：

```text
conv3(s1)  R=5  jump=1
pool2(s2)  R=6  jump=2      ← 只 +1，但 jump 翻倍
conv3(s1)  R=10 jump=2      ← 这一步开始 +4
```

**池化真正的价值不是缩尺寸，是把 jump 翻倍**：之后每个卷积都 +4 而不是 +2，**感受野涨得快一倍**。这就是真实网络"卷积-池化-卷积-池化"交替的原因。

## 六、梯度法怎么测（`measure_rf` 的原理与三个空）

### 原理

```text
输入 x → net(x) → 取输出中心一个点 → backward → 看 x.grad 哪些位置非零
```

**为什么成立**：那个输出点只由感受野内的输入算出来，**范围外没有路径 → 梯度恒为 0**。

### 关键三行

```python
out[0, 0, r, c].backward()              # 空1：在"那一个点"上做反向
mask = x.grad[0, 0].abs() > 0           # 空2：绝对值 + 阈值 → 布尔掩码
rf  = idx[:, 0].max() - idx[:, 0].min() + 1   # 空3：含两端所以 +1
```

### 为什么必须先有 `out = net(x)`

**两件事同时发生**：

1. **算数值**：`(1,1,64,64)` 的输入变成 `(1,1,64,64)` 的新特征图（p=1,s=1 尺寸不变），但里面的数全变了
2. **建计算图**：`out.grad_fn = <ConvolutionBackward0>`，**PyTorch 一边算一边记"这些数是怎么算出来的"**

**没有这一步，就没有图；没有图，`backward()` 无路可走。**

### `out[0,0,r,c]` 是什么

从 `(1,1,64,64)` 里取"第 0 张图、第 0 通道、第 r 行、第 c 列"**那一个数**：

```text
out            (1, 1, 64, 64)
out[0]         (1, 64, 64)
out[0,0]       (64, 64)
out[0,0,32]    (64,)
out[0,0,32,32] ()           ← shape 空括号 = 标量，才能 backward
```

**实测**：

```text
out[0,0,32,32]      = tensor(-0.1938, grad_fn=<SelectBackward0>)
它的 shape          = ()      ndim = 0
对比 out[0,0,32:33,32:33] shape = (1,1)   ← 只有一个数，但是二维，不能 backward
```

**为什么要取正中心**：边界上的点感受野会被 padding 截掉一部分，测出来偏小。**中心点（32,32）离四边都 32 像素，7×7 窗口能完整落在图里。**

### 范围外是 `0` 还是 `None`（空 4 答案）

**是 `0.0`，不是 `None`。** 实测（3 层，64×64）：

```text
x.grad 的 shape : (1, 1, 64, 64)      ← 和输入完全同形状
范围外(角落 0,0) : 0.0
范围内(32,32)    : 0.0785713
等于 0 的像素数   : 4047   非零: 49   总: 4096
```

**机制**：`backward()` 先给所有参与的叶子**分配一整块同形状、填满 0 的梯度**，然后只往有路径的地方累加。**没路径 = 停在初始的 0。**

**什么时候才是 `None`**：

| 情况 | grad |
|---|---|
| 张量完全没参与前向 | **None** |
| 没写 `requires_grad=True` | None |
| 非叶子张量（中间结果） | None（只有 grad_fn） |
| **叶子参与了，但某像素没被用到** | **0.0**（今天的情况） |

**"0 = 查过，答案是没用到；None = 压根没进这张图。"**

## 七、实测里踩到的三个数值坑（都改掉了）

### 坑 1：固定阈值会把最外圈切掉

原来写 `abs() > 1e-12`，**20 层时算出 40 而不是 41**。

**原因**：层数越多，梯度按指数衰减（中心 1.6e-07，最外圈可能 1e-13），**固定阈值把真正属于感受野的最外一圈误判成 0**。

```text
用 1e-12  → 40 (WRONG)
用 0       → 41 (OK)    ← 感受野内梯度理论上必不为 0
```

**教训（和 day2 的 `.3e` 同源）**：**涉及指数衰减的量，别用固定绝对阈值。**

### 坑 2：`print(x.grad)` 刷屏

一个 64×64 的梯度打出来几十行，20 层还会打 1400 多行索引（`print(idx)`）。**改成一行摘要**：

```text
非零像素 1462/4096 | 包围盒 41x41 | 行范围 [12, 52] | 输入 64
```

### 坑 3：偶数边长导致不对称

`out.shape[-1] // 2` 在偶数尺寸下不是几何中心，**E 测出 24×22**。修法：

```python
rf = max(rf_h, rf_w)
```

### 坑 4：返回 tensor 不是整数

`rf` 原来是 `tensor(3)`，和公式的 `3` 不好比。**统一 `.item()`。**

## 八、"3 个 3×3 = 1 个 7×7"—— 三层含义，必须分开说（今天最值钱）

这句话到处传，但它其实是**三个不同命题**，混在一起必答错。

### 第 1 层：感受野相同（真）

```text
3 个 3×3  → RF 7
1 个 7×7  → RF 7
```

### 第 2 层：参数量和算力更省（真）

C_in = C_out = 64：

| 方案 | 参数 | MACs（224×224） |
|---|---|---|
| 1 个 7×7 | **200,768** | **10,070,523,904** |
| 3 个 3×3 | **110,784** | **5,549,064,192** |
| 比值 | 1.8148 | 1.8148 |
| 省 | **44.9%** | **44.9%** |

**两者省的比例完全相同，因为都只差一个 `k²`（49 vs 27）。**

### 第 3 层：函数等价 —— 只在"内部"（这里要诚实）

用 **full 卷积把三个 3×3 合成一个 7×7**，再和堆叠网络逐点比：

```text
内部（离边界 ≥3 像素）最大差异 : 3.43e-05     ← 等价（float32 噪声）
整体最大差异                  : 55.07
第 0 行最大差异               : 48.54          ← 完全不等价
```

**为什么边界差这么多**：**补 0 的次数不同。**

```text
3 层 3×3 → 补了 3 次 0，每一层都吃掉一圈有效像素
1 层 7×7 → 只补 1 次 0
→ 边界处"有效像素的构成"不一样，是两个不同的函数
```

**所以准确说法（背这三句）**：

> **① 感受野等价；② 函数只在内部等价（3e-05），边界不等价（48.5）；③ 参数量和算力不等价，3 个 3×3 反而省 44.9%。再补一句：中间可以插非线性，表达力更强。**

### 附：合成核的两个技术细节

**① 为什么必须 `flip(2,3)`**

PyTorch 的 `conv2d` 实际算的是**互相关**（不翻转核），而"核合成"要数学卷积（要翻转）。实测：

```text
用 flip    内部差异 3.05e-05   ✓
不 flip    内部差异 1.43e+02   ✗ 差 143
```

`flip(2,3)` = 在 H、W 两个维度上翻转 = **把核旋转 180°**。

**② 为什么 `padding=2`**

`k-1 = 2`，这是 **"full 卷积"** 的补法：两个 3×3 做 full 卷积得 5×5，再做得 7×7。**不补就只剩 1×1，信息全丢。**

**③ 夹了 ReLU 就不成立**

```text
纯线性 3 层         差异 3.05e-05
中间夹 ReLU         差异 1.31e+02   ← 合成失效
```

**非线性不满足可合并。所以真实网络里堆叠小核比单个大核更强——"等价"只是线性层面的说法。**

### 这个方法的正名

**卷积核合成**，数学名字是**卷积的结合律**：

```text
(f ⋆ g) ⋆ h  =  f ⋆ (g ⋆ h)
```

**工程里的三处真实用途**：

| 用途 | 做什么 |
|---|---|
| **RepVGG 重参数化** | 训练时 3×3 + 1×1 + identity 三分支，推理时合成一个 3×3 |
| **Conv-BN 折叠** | BN 是仿射变换，可整块乘进卷积权重，推理时 BN 层消失 |
| **减少访存** | 3 层合成 1 层，少两次中间特征图读写（**算力没省，反而更贵**：49 > 27） |

## 九、大核 vs 小核，到底选哪个

**唯一相同的是感受野；其余全不同。**

| 维度 | 3 个 3×3 | 1 个 7×7 | 谁赢 |
|---|---|---|---|
| 参数 / MACs | 27C² | 49C² | 3×3（省 44.9%） |
| 非线性次数 | 3 次（可插 2 个 ReLU） | 1 次 | 3×3 |
| 延迟 / kernel 启动 | 3 次 | 1 次 | 7×7 |
| 中间显存搬运 | 3 张特征图 | 1 张 | 7×7 |
| 表达能力（参数维度） | 27 维子集 | 49 维全集 | 看任务 |

**四类场景怎么选**：

```text
① 通道多（C ≥ 64）、网络深、要精度 → 3×3 堆叠（VGG/ResNet/YOLO 的标准做法）
② 浅层、输入通道少（3 通道 RGB）    → 大核更便宜（AlexNet 首层 11×11：7×7×3×64 只有 9,408）
③ 边缘设备、延迟敏感              → 少层（3 层多 2 次启动 + 2 张中间图）
④ depthwise 卷积                → 大核重新划算（k² 不再乘 C_in×C_out，ConvNeXt 用 7×7）
```

**选型一句话**：**被精度卡住用 3×3，被延迟/访存卡住用大核或少层，被参数量卡住用 3×3。**

**关于"参数不等价但为什么还叫等价"**：说"等价"只指"**内部能产生相同输出**"这一件事。**3 个 3×3 是 7×7 的一个 27 维子集，而任意 49 维的 7×7 核一般拆不成三个 3×3。** 所以严格说是**单向包含**：任何 3 层 3×3 都能被某个 7×7 复现，反过来不一定。

## 十、参数量与 MACs 怎么算（任务 5）

```text
参数：k² × C_in × C_out + C_out        （与图片大小无关）
MACs：权重数 × H_out × W_out           （与输出大小有关）
```

**C = 64 的两行算术**：

```text
7×7：  7*7*64*64 + 64 = 49*4096 + 64 = 200,704 + 64 = 200,768
3×3：  3*3*64*64 + 64 =  9*4096 + 64 =  36,864 + 64 =  36,928
3 层： 36,928 * 3 = 110,784

MACs(7×7)   = 200,704 * 224*224 = 200,704 * 50,176 = 10,070,523,904
MACs(3×3×3) = 110,592 * 50,176                      =  5,549,064,192
```

**注意 MACs 用的是"不含 bias 的权重数"**（bias 每个位置只加一次，不参与乘加）。

**捷径**：`MACs = 权重个数 × 输出位置数` —— 这就是"权重共享"的直接后果，**一个权重被用了 H_out×W_out 次**。

## 十一、池化到底是什么（今天顺手补的概念）

**定义**：用 k×k 窗口把图切块，每块只留**一个代表值**（最大或平均）。**尺寸减半、通道不变、参数量 0。**

**实测 4×4 → 2×2**：

```text
输入            最大池化          平均池化
1  3 | 2  4     ┌─────┐          ┌──────────────┐
5  6 | 7  8  →  │ 6  8│    /     │ 3.75   5.25 │
2  1 | 0  2     │ 9  3│          │ 4.00   1.50 │
9  4 | 3  1     └─────┘          └──────────────┘
```

### 参数分别是什么

`nn.MaxPool2d(2, 2)`：

| 参数 | 值 | 含义 |
|---|---|---|
| `kernel_size` | 2 | 窗口 2×2（一次看 4 个像素） |
| `stride` | 2 | 每次挪 2 格（不重叠） |
| `padding` | 0 | 边界补不补 |
| — | — | **没有 weight、没有 bias** |

**"参数"两层意思，别混**：

```text
可学习参数（weight/bias）：池化 = 0 个，训练时一点不改
超参数（设置值）        ：kernel / stride / padding，你自己定的规则
```

**`MaxPool2d(2)` 只写一个 2 时，stride 默认等于 2。** 写成 `(2,1)` 就是重叠池化。

### 输出尺寸用同一个公式

```text
out = (H + 2p - k)/s + 1
4×4, k=2, s=2, p=0 → (4-2)/2 + 1 = 2
224×224            → 112×112
```

**池化也不改通道数**：`64×224×224 → 64×112×112`。

### 三种常见池化

| 层 | 挑什么 | 用途 |
|---|---|---|
| `MaxPool2d(2,2)` | 块内最大值 | CNN 最常用，保留最强响应 |
| `AvgPool2d(2,2)` | 块内平均值 | 更平滑，分割网络常用 |
| `AdaptiveAvgPool2d(1)` | 整图平均成 1×1 | **分类网络最后一步**，任意尺寸都能压成固定向量 |

### 池化为什么存在

```text
① 计算量砍到 1/4（面积 1/4）
② 把 jump 翻倍 → 后面每层 RF 增长快一倍
③ 轻微平移不变性 → 小抖动不敏感（对小目标也是坏事）
```

## 十二、顺手理清：尺寸 vs 通道（今天问过，容易混）

**尺寸（H、W）= "图上有多少个位置"；通道（C）= "每个位置存了几个数"。**

**两个旋钮互相独立**：

| 改什么 | 调哪个参数 | 另一个 |
|---|---|---|
| 改通道 3 → 64 | `out_channels` | 尺寸**不变** |
| 改尺寸 224 → 112 | `k / p / s` | 通道**不变** |
| 改参数量 | `C_in / C_out / k` | **与尺寸完全无关** |

**最直接的证据：1×1 卷积**

```python
nn.Conv2d(64, 128, 1)      # 224×224×64 → 224×224×128：通道翻倍，尺寸一个像素没动
nn.MaxPool2d(2, 2)         # 224×224×64 → 112×112×64：尺寸减半，通道没动
```

**三个常见误解**：

```text
✗ 通道多了图就变大      → 通道是"深度"方向，不影响 H/W
✗ 64 个通道 = 64 张图    → 是同一张图的 64 种特征描述，位置对齐
✗ 参数量随图片变大       → 一个核全图滑动复用，参数量与 H/W 无关（MACs 才变）
```

**记住 shape `(N, C, H, W)`：第 2 位问"描述多丰富"，第 3、4 位问"空间分辨率"。**

## 十三、张量索引怎么用（今天用的那一套）

**规则只有一条：整数索引 = 删掉该维度；切片索引 = 保留该维度。**

用 `x = torch.arange(32).view(1,2,4,4)`（通道 0 = 0~15，通道 1 = 16~31）实测：

| 写法 | 形状 | 结果 | 含义 |
|---|---|---|---|
| `x[0]` | (2,4,4) | — | 去掉 batch 维 |
| `x[0,0]` | (4,4) | 0~15 | 第 1 张图的第 1 个通道 |
| `x[0,0,1]` | (4,) | [4,5,6,7] | 第 1 行 |
| `x[0,0,1,2]` | **()** | 6.0 | **一个数**（能 backward） |
| `x[0,0,1:3]` | (2,4) | 第 1、2 行 | 切片保留维度 |
| `x[0,0,1:3,2:4]` | (2,2) | [[6,7],[10,11]] | 一小块区域 |
| `x[0,0,-1,-1]` | () | 15.0 | `-1` = 最后一个 |
| `x[:,:,::2,::2]` | (1,2,2,2) | 隔一取一 | 下采样 |

**四个实际场景**：

```text
① 测感受野      out[0,0,r,c]
② 可视化        x[0].permute(1,2,0)     （matplotlib 要 H,W,C 顺序）
③ 单通道        out[0,3]
④ 取一块区域     img[0,0,100:150,200:260]
```

**两个技巧**：

```text
x[0, ..., -1]       省略号：维度多时省事
x[0][None]          None 加维，等价 x[0].unsqueeze(0)：把 (C,H,W) 补回 (1,C,H,W) 喂给模型
```

## 十四、有效感受野与真实网络（理解"理论不等于实际"）

**理论 RF 大，不代表"实际重点看那么多"。** 用梯度能量统计（30 次随机初始化）：

| 结构 | 中心 3×3 占总梯度比例 |
|---|---|
| 3 个 3×3 | **35.36%**（标准差 8.62） |
| 1 个 7×7 | **19.71%**（标准差 3.24） |

**意思**：3 层 3×3 理论上看到 7×7，但**能量三分之一集中在中心 3×3**；单个 7×7 分布更均匀。**这叫"有效感受野远小于理论感受野"（ERF）。**

**VGG16 实测（13 个 3×3 + 5 个 2×2 池化）**：

```text
conv5_3 后   RF = 196
pool5 后     RF = 212        ← 输入 224，还差 12 像素没覆盖
```

**但 VGG 依然能分类整图，因为**：pool5 后输出 7×7，**每个点各覆盖 212 个像素，7×7 摊开就覆盖全图**。

> **不是靠单个神经元看全图，是靠整张特征图拼接。**

**这一条对缺陷检测特别重要**：大缺陷需要检测头有大 RF，小缺陷需要高分辨率特征图，**两个需求打架 → 所以有 FPN、UNet。**

## 十五、stride 的代价（任务 4）

**同样的 3 层，s=1 vs s=2**：

| 层数 | RF（s=1） | RF（s=2） | 输出尺寸（输入 32） |
|---|---|---|---|
| 1 | 3 | 3 | 16×16 |
| 2 | 5 | 7 | 8×8 |
| 3 | 7 | **15** | **4×4** |

**代价的正确说法（我一开始填错了）**：

```text
感受野 7 → 15（翻倍）
但空间分辨率 32×32 → 4×4
每维 1/8，总面积只剩 1/64
```

**不是"降低一半"**——那是单层的代价，三层是累积的。

**这对检测意味着什么**：4×4 的特征图上**定位不了 3 像素的小缺陷**。**所以"提 RF"和"保分辨率"是一对根本矛盾，所有多尺度结构都在解这个矛盾。**
